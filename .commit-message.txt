Publish as an npm package and name it in the catalog

The link: install was removed by DSH itself, and the market reported the
row as "failed to fetch market version" because it asked npm for a
package that did not exist: dshmarket resolves a plugin's version by
package name, and a catalog entry without an npm field has no npm
identity to ask with.

installTargetFor prefers the npm name over the git source, so naming the
package in the entry fixes the version question, lets discovery judge
compatibility against the host, and makes the install a 2.5 MB registry
fetch instead of a 14 MB repository clone.

@deepseek-ai/cordis is declared an optional peer on purpose. A
non-optional peer makes pnpm pull the host's whole dependency tree into
the user profile, which is what broke the install of
dsh-workbuddy-trae-qoder-connect at 165 packages. This plugin imports
nothing from that tree.

The package is publishable now: npm pack produces 10 files, 2.5 MB
compressed. Not yet published; the registry has no such package.
